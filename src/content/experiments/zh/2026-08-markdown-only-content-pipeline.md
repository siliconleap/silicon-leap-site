想做内容想了很久，一直没开工。

工具在比较，方案在研究，最佳实践在找，就是没有一篇发出来。这个状态持续得越久，越难开始。

后来我换了个办法：给「想试的东西」找一个容器。每件事都当成一次实验——一个目录，一份记录，一次公开。做完就发，不等完美方案。

而第一个实验，就是用 AI 把这套记录机制本身做出来。

半天做完。然后我发现它没法用。

## 这套东西是什么

两个仓库，全是纯文本：

| 仓库 | 角色 |
| --- | --- |
| `silicon-leap-forge` | 流水线本体：skill、平台配置、模板、约定文档 |
| `silicon-leap-lab` | 实验记录，流水线的输入和输出都在这里 |

两个 skill：`experiment-plan` 把一句话选题变成能照着跑的实验目录；`content-forge` 把跑完的实验变成各平台初稿。环境是 macOS 加 Claude Code CLI 加 git，没装别的东西。

要验证的问题：只靠 Markdown 约定加 skill，不用 n8n、Coze、Dify，不用服务器和数据库，这条流水线能不能真跑起来。

答案是能。但这是整个实验里最不重要的结论。

## 完整的外观，空的内容

生成出来的 skill 有 frontmatter，有分步流程，有硬约束清单，还有验收标准。该有的都有，读起来像个成熟的东西。

我批准它只花了一句话：「可以，写出来。」

直到我让它真的跑一遍。

产出的第一篇小红书文案，枯燥得读不下去。不是写错了，是没法看。

![配置与模板的实际内容对照](assets/01-contradiction.png)
*图 1：配置与模板的实际内容对照，来源为本次实验的两个文件*

翻开模板才看见根子。里面硬编码了一套骨架：「结果」「有效的」「踩的坑」，三段列表。

而在同一套配置的另一个文件里，写着这么一句：

> 陈述完事实就转进列表。没有处境，没有反应，数字没有参照系。

配置在骂模板，模板在违反配置。

最麻烦的地方在于：两个文件分开看，每一个都是对的。矛盾只在真跑一遍、读到产出的那一刻才出现。

## 一条从没能执行的规则

再往下翻，配图那一节写着：输出 SVG 源文件，由人渲染。

我查了这台机器。rsvg-convert、ImageMagick、wkhtmltoimage，一个都没装。

这条规则从写下的那天起，就没有执行的可能。它读起来完全合理，也确实符合「纯文本、可版本控制」的设计目标，唯独没人确认过这台机器上有没有渲染器。

## 为什么会这样

后来才想明白。

AI 的训练和生成，本质是已有数据的大规模统计概率。输出天然回归均值。而均值就是平庸。

这不是能力不足，是它的工作原理决定的。它不会主动想到「这个模板和那份配置自相矛盾」，也不会主动确认「这台机器上到底有没有渲染器」——这些都不是统计意义上的常见做法。

换个更强的模型也一样，只会得到一个更精致的均值。

所以打磨的地方不在产物上，在指令上。改一遍产出只修好一篇文档，写清楚「不要什么」才修好之后的每一次。

## 拿到了什么

回过头把要求逐条写进 skill：

- 反 AI 腔负面清单，七类。套路化小标题、benefit 列表、空泛 buzzword、作文骨架、没数据撑的程度词、万能收尾、连用的排比句
- 叙事必须讲全四件事：为什么选这个实验、中间哪些失败、成果是什么、能否复制
- 中文行文规则：句子短，主语在前，少用「被」，删掉「进行了」「实现了」这类壳子
- 模板从三段列表改回叙事结构
- 配图必须真的渲染出来，不能只写「配图说明」

![三层职责划分](assets/02-layers.png)
*图 2：三层职责划分，来源为本次实验的 Artifacts 段*

更管用的是把确定性的部分沉进脚本。目录骨架、七段标题、校验、配图渲染，这些不需要判断，交给 shell 脚本。剩下要判断的才归 agent，最后真正要拍板的才归人。

校验脚本写完第一次跑，抓出四处死链。此前那是人工 review 才发现的。

配图链路最后落在 HTML 渲染成 PNG，用系统自带的 Chrome，零额外安装。HTML 进 git、可 diff，PNG 是产物。

## 哪些能复制，哪些不能

能复制的是方法。把确定性沉进脚本，把「不要什么」写进指令，这两条跟用哪个模型、做什么题目都没关系。

不能复制的是这次的具体产物。平台配置照着这几个渠道写的，换个渠道要重写。

还有一处彻底失败：视频渠道交付不了。脚本、标题、封面方案都能生成，因为它们是纯文本。但录屏为 0，剪辑、配音、字幕都没有自动化路径。纯文本这套办法在前几个渠道成立，到视频这里失效了。

## 需要说明的地方

这份记录是回溯补写的。`plan.md` 本该在开跑前写，实际是事后还原，所以「预期反直觉点」那一节只能删掉换成「实际发现」——事后补的预测没有价值。

耗时和 token 全程没记录，而且 `--reset-author` 重置了 commit 时间戳，git 历史也当不了耗时依据。

没有录屏：asciinema 从未装过，更根本的是工作方式变了——人跟 agent 对话，agent 执行，终端里没有「人的操作过程」可录。真正的过程记录是对话本身，而这次没把它当素材保存。
